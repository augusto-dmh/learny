# Provider adapter architecture — ports, operator routing, and end-user choice

*Research date: 2026-09-07. Code-read date: 2026-09-07, on the tree containing PR #68's spend rails. Scope: what it would take to (a) add more LLM providers, (b) let the OPERATOR route between them (fallback / effort / caching), and (c) optionally let the END USER choose a provider — given how Learny's provider integration is actually built (ADR-0007 ports, ADR-0009 no orchestration framework, ADR-0020 Claude primary; roadmap row `cheaper-intelligence`, `.specs/project/ROADMAP.md:146`, requires the ADR-0020 amendment first). Read-only survey; no code changed. Feeds the ADR-0020 amendment; builds on `docs/research/2026-09-03/rq14-multi-provider-models.md` and `rq15-ai-cost-optimization.md`.*

## TL;DR

**Verdict 1 — a new (OpenAI-compatible) generation adapter is a cycle-sized build with a feature-degradation bill attached.** The `GenerationPort` surface (`backend/app/domain/ports.py:658-730`) is genuinely provider-shaped, not Anthropic-shaped: `model` identity, `generate`, `generate_stream`, and Learny-owned DTOs. But the Anthropic adapter leans on four provider-specific capabilities, and only two have portable equivalents on generic OpenAI-compatible endpoints: structured outputs (partial — `response_format` json_schema is broadly supported) and prompt caching (degraded — automatic prefix caching, no manual breakpoints, which kills the rq15 breakpoint optimizations). The Citations API has **no** equivalent, and thinking/effort control has only vendor-specific partials. The port already tolerates absence (`spans` and `usage` default empty, `backend/app/domain/entities.py:495-508`), and grounding (ADR-0003) re-verifies whatever the adapter reports — but an adapter that reports no citations turns every answer-mode turn into not-found (AD-027), so degradation must be declared per profile, never discovered in production.

**Verdict 2 — operator routing (fallback/effort/caching) is a small-to-medium, one-cycle build once two prerequisites land: a Learny-owned provider-error taxonomy and per-profile pricing.** The natural shape is a routing adapter that itself implements `GenerationPort`, built at the existing factories (`backend/app/infrastructure/answering/__init__.py:29-56`) from a settings-declared profile registry — no framework, ADR-0007/0009 intact. Spend accounting is already provider-agnostic (`TokenUsage` × `TokenPrices`, `backend/app/application/budget.py:115-122`); it needs the single price catalog (`backend/app/core/config.py:256-258`) split per profile. The nightly eval gate already records `generation_model` per case (`backend/app/eval/judge.py:321`) and publishes nightly (`eval.yml:15-16`), so a candidate profile can be judged before promotion with no new harness. **The hidden risk is the quiz batch path**: `QuizDeckHandle` carries a `provider` field (`backend/app/domain/entities.py:868`) but the poll tasks rebuild the adapter from *current settings* (`backend/app/worker/tasks.py:616,662` via `backend/app/infrastructure/quiz/__init__.py:37`), so flipping providers mid-flight would poll another vendor's API with a foreign batch id. Streaming also bounds fallback: a stream that has already emitted deltas cannot be retried.

**Verdict 3 — end-user (learner) provider choice is a roadmap of its own, not a cycle; defer it.** Nothing per-user exists in the AI plane: the `User` entity carries email/ToS/verification only (`backend/app/domain/entities.py:26-43`), adapters are built process-wide from env settings under `lru_cache` (`backend/app/infrastructure/web/dependencies.py:619-622`), and there is **no encryption-at-rest helper anywhere in `backend/app`** (the only "encrypted" matches are docstrings about encrypted PDFs). BYO keys would add: a per-user settings table, a new crypto dependency plus master-key management, per-request adapter construction, key lifecycle/revocation, and a new abuse surface (a user-supplied `base_url` would make Learny an open relay for book content — BYO must be key-only against operator-curated profiles). The cycle-sized slice is "learner picks among operator-curated house profiles" (no keys, no crypto), and even that depends on verdict 2's router existing first. Recommendation: build operator routing in the `cheaper-intelligence` cycle; leave end-user choice to a future RFC alongside pricing (RQ10).

## 1. Adapter surface: what the ports declare, what the adapters actually use

### 1.1 The ports

Three AI ports exist, all `typing.Protocol`, no SDK/HTTP/SQL types cross them (ADR-0007):

- **`GenerationPort`** — `backend/app/domain/ports.py:658-730`. `model: str` readable without a network call (`ports.py:685`), `generate(...)` (`ports.py:687`) and `generate_stream(...)` (`ports.py:709`) take `message`, explicit `mode`, `evidence`, `history`, `target_section_path`, `tutor_phase`, `hint_level`, and return the Learny-owned `GeneratedAnswer` (`backend/app/domain/entities.py:486-508`) or a stream of `AnswerStreamEvent`. Operational failure **raises**; the application service maps any raise to `AnswerGenerationFailed` (`ports.py:700-706`; `backend/app/application/errors.py:129`). There is no typed error taxonomy — anything raised is operationally equivalent.
- **`QuizGenerationPort`** — `ports.py:840-898`. Async-by-design: `begin_deck` → `QuizDeckHandle` (`ports.py:857`), `collect_deck` polls until non-`None` (`ports.py:865`); plus synchronous `suggest_cards` (`ports.py:874`) and `suggest_note_cards` (`ports.py:887`).
- **`EmbeddingPort`** — `ports.py:556-577`. `model` is `{model}@{dims}` semantics (`ports.py:562-569`), `embed_query`/`embed_documents` (`ports.py:571-576`). Per-chunk model stamping is ADR-0019's versioning key (`ports.py:606-613`).

**Embeddings** (`backend/app/infrastructure/embeddings/openai.py`): the adapter sends `model`, `input`, `dimensions` (`openai.py:86-91`) and sub-batches under 2048-input/250k-token caps (`:23-24`). The `dimensions` parameter is the partial-equivalence trap: only MRL-capable models honor it, and ADR-0019 couples the stored identity to `vector(1536)` (`config.py:163-178`). Recommendation from rq14 stands — do not diversify embeddings; a switch is a full re-embed plus possible schema change.

### 1.3 What the port must declare vs. hide

The ports need **no** new members. Everything provider-specific in §1.2 is already either adapter-internal (caching, batches, schemas, citations) or a constructor parameter (key, model, max_tokens, effort — `answering/anthropic.py:395-408`). What multi-provider adds is *metadata beside the port*, not inside it: a per-profile capability/price declaration consumed by the router (§2) and by spend accounting. If runtime checks ever feel necessary ("can this profile serve a grounded Ask?"), prefer declaring it in the profile registry over growing `GenerationPort` — the registry is a config object, the port is a contract three adapters and the eval harness already satisfy.

## 2. Where provider/model selection lives today, and the minimal operator router

### 2.1 Current selection mechanics

- **Settings names** (`backend/app/core/config.py`): `generation_provider` (:235, shared by the answer *and* quiz factories), `anthropic_api_key` (:236), `generation_model` (:237), `generation_effort` (:238, `Literal["low","medium","high","xhigh","max"]`), `generation_max_tokens` (:239), `judge_model` (:240), `eval_max_cases` (:241), `eval_budget_usd` (:246); quiz: `quiz_model` (:309) plus batch knobs (:322-323); embeddings: `embedding_dim` (:174), `embedding_provider` (:175), `openai_api_key` (:176), `embedding_model` (:177).
- **Factories** (the composition roots): `build_generation_adapter` (`backend/app/infrastructure/answering/__init__.py:29-56`), `build_quiz_adapter` (`backend/app/infrastructure/quiz/__init__.py:28-50`), `build_embedding_adapter` (`backend/app/infrastructure/embeddings/__init__.py:28-45`). Each is a pure function of `Settings`, fails fast on a missing key (`answering/__init__.py:46-49`), and raises `ValueError` on an unknown provider rather than silently falling back (`answering/__init__.py:56`).
- **Consumption cadence**: web builds the generation adapter **once per process** under `@lru_cache` (`dependencies.py:619-622`); quiz and embedding adapters are rebuilt per request/task (`dependencies.py:1005,1011`; the hot-path query embed at `:602`). Worker tasks rebuild per invocation (`backend/app/worker/tasks.py:352,414,457-458,531-532`) and the batch poll tasks rebuild from settings (`tasks.py:616,662`).

### 2.2 The minimal router that keeps ADR-0007/0009

**A provider profile registry + one routing adapter.** Replace the two-string switch (`generation_provider` + `generation_model`) with a settings-declared ordered list of profiles, e.g. `LEARNY_GENERATION_PROFILES="anthropic-sonnet5,economy-fireworks"` where each profile names: adapter kind (`anthropic` | `openai-compatible` | `local`), model, base URL, API-key *env-var name*, effort, max_tokens, and its own price pair. A `RoutingGenerationAdapter` implements `GenerationPort` itself and walks the chain; application services (`conversations.py:924-946`) never learn it exists. This is exactly the ADR-0007 shape — "fallback routing under Learny's control" (`docs/adr/0007-...md`, implementation model item 1-4) — and touches no framework (ADR-0009).

What each routing concern needs, concretely:

- **Failure semantics / retryable-across-providers.** Today adapters raise untyped exceptions; the only classification is a logging side-channel for 4xx (`answering/anthropic.py:299-328`, re-raised at `:480-482,593-595`). The prerequisite is a small Learny-owned taxonomy — roughly `Timeout`, `RateLimited`, `ProviderUnavailable` (429/5xx/overload), `RequestRejected` (4xx shape/auth) — translated inside each adapter. Fallback rules that fall out: timeouts and `ProviderUnavailable` are retryable-across-providers; `RateLimited` is retryable on the *same* provider after backoff or across after one attempt; `RequestRejected` is **not** worth re-sending to a different provider's adapter blindly (the shapes differ — citations documents vs json_schema — so only a profile whose adapter builds a different shape may be tried). Wall-clock bounds already exist to anchor timeout classification: `_GENERATE_TIMEOUT_S = 120` (`answering/anthropic.py:70`) and `_SUGGEST_TIMEOUT_S = 30` (`quiz/anthropic.py:44`).
- **Streaming bounds the fallback window.** A buffered `generate` can fail over wholesale (nothing has been emitted). A stream can only fail over **before the first delta**: after `AnswerTextDelta`s are on the wire, the SSE contract (zero+ deltas then exactly one authoritative `AnswerCompleted`, `ports.py:720-729`; mapped at `streaming.py:74,108`) has no "rewind" — the router must decide at stream-open and then commit. This is a one-line rule to write into the amendment because it silently caps what "fallback" means for Teach.
- **Effort/caching stay per-profile.** Effort is already a constructor arg (`answering/anthropic.py:401`); the registry carries it per profile. Caching needs no routing decision at all (§1.2).
- **Spend accounting stays provider-agnostic — with one change.** The ledger is a `(user_id, day)` upsert of micros (`AiSpendDayRepository`, `ports.py:1459-1482`), debited after the port returns (`conversations.py:948-963`) and asserted before it (:784-785, kind from `spend_kind` :100-110). `usage_micros` multiplies a **single** price catalog from settings (`budget.py:115-122`; catalog at `config.py:256-258`). Routing breaks the single catalog: an economy profile debited at Sonnet prices trips the `$0.50` daily cap (`config.py:255`) far too early (over-charging is conservative but wrong), and a pricier fallback debited at economy prices would under-charge. Fix: resolve prices from the routed profile — `GeneratedAnswer.model` already rides back across the port (`entities.py:503`), so the debit site can map model → profile prices, or the router can stamp the price pair onto the result. The deck path's one-time spend marker (`claim_spend`, conditional UPDATE at `backend/app/infrastructure/db/repositories.py:1990-2006`, consumed at `worker/tasks.py:564-571`) is already provider-agnostic and idempotent — no change needed.
- **The quiz batch path must pin its provider.** `QuizDeckHandle.provider` exists (`entities.py:868`) but nothing reads it: the poll tasks call `build_quiz_adapter(get_settings())` (`tasks.py:616,662`), which selects from *current* settings (`quiz/__init__.py:37`). An operator flip between `begin_deck` and `collect_deck` would poll vendor B with vendor A's batch id. The registry makes this a one-line fix (select the adapter named by `handle.provider`) and it is a prerequisite for any routing at all.
- **The eval gate plugs in before promotion.** The harness already: records `generation_model` per JSONL case (`judge.py:321`), caps cases (`eval_max_cases`, `config.py:241`), asserts aggregate thresholds only under `LEARNY_EVAL_GATE=1` (`judge.py:44-48,330`), and runs nightly on cron publishing to the `eval-results` branch (`.github/workflows/eval.yml:15-16,26`). A candidate profile is therefore promotable by pure process: run the nightly with `LEARNY_GENERATION_MODEL` pointed at the candidate (the workflow's secret-skip at `eval.yml:50-58` shows the env-driven pattern), require green aggregates on the 12 snapshots, and only then reorder the profile registry. No new code is strictly required; a second scheduled job (or a workflow matrix) makes it routine. This is rq14's gate (faithfulness ≥ 0.90, relevancy ≥ 3.1, `citation_valid` = 100%) with the mechanics Learny already owns.

## 3. End-user-selectable providers: what it would actually take

### 3.1 What exists today (very little)

- **No per-user preferences anywhere.** `User` holds `id/email/created_at/accepted_tos_at/email_verified_at` (`entities.py:26-43`). There is no user-settings table among migrations `0001`-`0028` (the last, `0028_quiz_deck_spend_marker.py`, adds only `spend_recorded_at`).
- **No key storage or crypto.** No encryption-at-rest helper exists in `backend/app` — the only "encrypt*" matches are docstrings about encrypted PDFs (`backend/app/application/errors.py:104`, `backend/app/infrastructure/ingestion/docling_pdf.py:20,95`). Secrets today are env-only by policy (`config.py:1-5`, NFR-SEC-003).
- **Adapter construction is process-shaped.** `get_generation` is `lru_cache`d per process (`dependencies.py:619-622`); the comment at `dependencies.py:998` records that building quiz adapters per request "would mint a provider SDK" — the current design assumes one identity per deployment.
- **The web/proxy seams are ready for a settings endpoint, though.** The Next proxy is pure transport (`frontend/app/lib/proxy.ts:9-11`), CSRF + HttpOnly-cookie auth is established (`frontend/app/lib/auth.ts:8-13`, `/api/auth/me` at `backend/app/infrastructure/web/auth.py:289-290`), and the account page (`frontend/app/(app)/account/page.tsx:16-21` → `AccountPanel`) is the natural surface. `MeResponse` (`auth.ts:23-25,30-35`) would grow a preferences block. No new auth mechanics needed.

### 3.2 The build items, by flavor

**Flavor A — learner picks among operator-curated house profiles** (no user keys):
1. Migration: `user_ai_preferences` (one row per user: profile id, timestamps) + repository port/adapter (the 20-port pattern in `ports.py` makes this mechanical).
2. Per-request adapter resolution: replace the `lru_cache` singleton with a two-tier lookup — user's profile if set and enabled, else the operator default — through a keyed cache or cheap per-request construction (the factories are pure; only the SDK client is heavy, and it builds lazily on first use, `answering/anthropic.py:415-421`).
3. Budget: house spend is house spend — `budget.py` applies unchanged, priced at the chosen profile's catalog (§2.2).
4. Degradation UX: the settings surface must state what the profile does (e.g., "economy: answers may cite less precisely") because answer-mode not-found collapses differ per profile (§1.2).
5. Frontend: account-page selector + `MeResponse` extension.

This is the cycle-sized slice, **but only after §2's router and per-profile pricing exist** — without them a learner-selectable profile has nothing to select.

**Flavor B — BYO key ("house model vs your key")** — everything in A, plus:
1. **Crypto**: a new dependency (e.g. Fernet/cryptography) and a master-key story (env/KMS-held `LEARNY_USER_KEY_MASTER`); envelope-encrypt keys at rest; never log them (NFR-SEC-004 discipline, `answering/anthropic.py:299-318` shows the redaction culture).
2. **Key lifecycle**: write/revoke/delete endpoints, revocation semantics for in-flight streams and queued deck jobs, and an audit posture for "Learny staff can never read this."
3. **Injection**: per-user adapter construction per request; connection-pool bounding per user; the `lru_cache` design retires or becomes a keyed LRU.
4. **Abuse surface — the sharp edge**: a BYO flow must accept **only the API key, never a base URL or provider kind** outside the curated registry. A user-supplied `base_url` turns Learny into an open relay that forwards copyrighted book text to arbitrary hosts (the exact Exfiltration concern rq14 §2 rules out for the operator, now user-triggered). SSRF egress controls would be needed if any URL field were ever allowed — recommend: never allow one.
5. **Spend-rails interplay**: a BYO-key user's provider bill is theirs, not Learny's — the USD ledger should **not** debit their day at house prices (it is meaningless and misleading). But keep: the integer counters (`daily_ask_cap`/`daily_teach_start_cap` — they are abuse ceilings measured in calls, `budget.py:110-113`, and calls still cost Learny egress/retrieval), the kill switch (an operator pause of the AI surface should pause BYO too, `budget.py:103-104`), and the user-keyed rate limits (`backend/app/infrastructure/web/rate_limit.py:165-181`, fail-closed Redis limiter `redis_rate_limit.py:37-84`). Library quotas (`quotas.py:62-77`) are orthogonal and unchanged. Embeddings stay house-only either way (the retrieval column is a shared `vector(1536)`, ADR-0019).

### 3.3 Honest complexity verdict

Flavor A alone is a defensible single cycle *after* the router cycle. Flavor B is a roadmap of its own: crypto + key management + lifecycle + abuse + billing-fairness + degradation UX is three-plus cycles and a security review, and its product value is gated on having a paying tier to sell it to (RQ10 territory). The ADR-0020 amendment should therefore *scope end-user choice out* explicitly, with Flavor A recorded as the future cheap path and BYO recorded as "revisit with pricing."

## 4. Decision inputs for the ADR-0020 amendment

Each decision point below is phrased as the question the amendment must answer, with a recommended answer grounded in §1-3.

1. **Does Claude remain the primary for Ask/Teach?** — Recommend **yes**. The Citations API is the only provider-computed, offset-verified citation source (§1.2), citations are the product promise (rq14; ADR-0003/0020), and the amend's job is to add tiers, not to dethrone the primary.
2. **Is a second adapter added now, or with the first concrete second provider?** — Recommend **with the first concrete profile** (the rq14-intended economy host: US-only Fireworks or Together), not speculatively; the factory pattern makes the wait cheap (`answering/__init__.py:42-56`).
3. **How is feature degradation declared?** — Recommend **per-profile capability flags in the settings registry** ("grounded-primary" vs "economy"), consumed by the router; never a port method, never a runtime probe. Ask/Teach fall back only to profiles that preserve acceptable grounding; otherwise they fail honest (`found=False` / `AnswerGenerationFailed`).
4. **Where does effort live?** — Recommend **adapter constructor parameter fed per profile** (status quo at `answering/anthropic.py:401`); the port never grows an effort argument; the rq15 "diet Ask to `low`, keep Teach `medium`" lands as profile values after the judge gate.
5. **What does fallback cover?** — Recommend **turn path auto-fallback under the streaming rule** (fail-over only before the first delta; §2.2); **deck path pins its provider at `begin_deck`** via `QuizDeckHandle.provider` (fix the settings-only poll at `worker/tasks.py:616,662` first) and retries within the provider rather than cross-provider, because a half-submitted batch has no portable second home.
6. **Which errors are retryable across providers?** — Recommend a minimal Learny-owned taxonomy (`Timeout`, `RateLimited`, `ProviderUnavailable`, `RequestRejected`) translated in each adapter; only timeout/unavailable cross providers; 4xx shape rejections do not.
7. **How does spend accounting stay honest across prices?** — Recommend **per-profile price catalogs** replacing the single `price_*` triple (`config.py:256-258`), resolved at the debit site via the routed profile (`GeneratedAnswer.model`, `entities.py:503`); ledger, counters, kill switch, and `claim_spend` idempotency unchanged.
8. **How does a model become default?** — Recommend **eval-gated promotion as process**: candidate profile judged nightly (`judge.py:321` model-recorded, thresholds `:44-48`, cron `eval.yml:15-16`) until green on the 12 snapshots; the operator then reorders the registry. A flip without a green nightly is a documented exception, not a habit.
9. **Do the rails apply to every profile?** — Recommend **yes**: `assert_generation` runs before any port touch (`conversations.py:784-785`) regardless of which adapter is behind it; rate limits stay user-keyed (`rate_limit.py:165-181`).
10. **Do embeddings diversify?** — Recommend **no** (ADR-0019 unchanged): `dimensions` is not portable across providers (`openai.py:86-91`), the column width is coupled (`config.py:174`), and a switch is a full re-embed.
11. **End-user provider choice: decide now or defer?** — Recommend **defer, explicitly**: scope the amendment to operator routing; record "curated house profiles per learner" as the future one-cycle path and BYO-key as a pricing-gated roadmap (§3.3). Decide nothing now that forecloses either (the profile registry and per-request factory resolution are compatible with both).
12. **What must the amendment forbid?** — Recommend restating ADR-0009's line for the new surface: no LiteLLM/OpenRouter/Portkey in the composition root (rq14 §3); routing logic lives in a Learny-owned adapter; user-supplied endpoints are never a configuration input.

### Closing decision-inputs list (compressed)

- Keep `GenerationPort` frozen; add capability metadata **beside** the port (profile registry), not inside it (§1.3).
- Prerequisite order for `cheaper-intelligence`: error taxonomy → provider-pinned batch polling → per-profile pricing → routing adapter → eval-gated promotion → (then) Haiku-for-Ask / economy-profile decisions from rq15.
- The single decision that most constrains fallback quality is §1.2's citations row: only a "grounded-primary" profile may serve Ask; everything else is explicitly degraded.
- End-user choice: Flavor A (curated profiles) is one cycle behind the router; Flavor B (BYO keys) is a separate roadmap gated on pricing — scope it out of ADR-0020's amendment.
